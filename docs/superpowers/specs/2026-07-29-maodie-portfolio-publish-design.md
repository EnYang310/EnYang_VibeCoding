# 圆头耄耋项目入库与 Vibe Coding 作品集重构设计

## 1. 目标

将“圆头耄耋智能配菜 Agent”以脱敏完整源码的形式加入
`EnYang310/EnYang_VibeCoding`，同时重构仓库目录和根 README，使仓库清楚表达：

- 这是由多个不同 Vibe Coding 作品组成的作品集，不是单一项目。
- 每个作品都从真实用户问题出发，覆盖产品判断、AI 方案和工程落地。
- 圆头耄耋项目既可作为产品案例阅读，也可检查完整实现。

## 2. 目录设计

```text
EnYang_VibeCoding/
├── README.md
├── AIGC电商海报及文案制作Agent.ipynb
├── AI智能简历.ipynb
├── Skills作品/
│   └── aipm-course-teacher/
├── 作品截图/
│   ├── AIGC电商海报Agent/
│   └── AI智能简历/
└── 圆头耄耋智能配菜Agent/
    ├── README.md
    ├── Dockerfile
    ├── .env.example
    ├── backend/
    ├── frontend/
    ├── tests/
    └── assets/
```

原 `skills/` 改名为 `Skills作品/`。原 `项目demo图片/` 不直接丢弃图片，
而是将图片按所属项目移动到 `作品截图/` 并重命名，再在同一次提交中更新所有
Markdown 引用，最后移除空的旧目录。

## 3. 圆头耄耋源码范围

保留：

- FastAPI 后端、Pydantic 契约和异步任务接口。
- Next.js / React 移动端界面。
- 菜单规划、营养回填、计划审核、换菜生成、换菜审核等业务 Skills。
- USDA 本地营养知识库和确定性热量重算。
- 菜位固定食材预算、全局换菜忙锁、审核返工和原子替换逻辑。
- 前后端测试、Dockerfile、依赖清单和环境变量示例。

排除：

- `.kimi-key`、真实 API Key 和其他凭据。
- 构建缓存、依赖目录、测试缓存、运行日志和临时文件。
- 与作品理解无关的内部实施计划、过程记录和发布压缩包。

公开源码统一通过环境变量读取密钥；`.env.example` 只提供占位符。

## 5. 项目 README 设计

项目 README 是完整案例文档，覆盖：

1. 一句话介绍、项目状态和核心价值。
2. 用户问题、目标用户、使用场景和产品目标。
3. 从拍摄食材到跟做菜谱的完整用户旅程。
4. 系统架构与数据流 Mermaid 图。
5. Agent、Skill、Tool、LLM 和确定性代码的职责边界。
6. 图片识别、菜单生成、USDA 热量回填、计划审核的工作流。
7. 换菜的固定预算、全局忙锁、三级审核、两次定向返工和原子替换。
8. 前后端技术栈、关键接口、状态管理和部署方式。
9. 测试策略、安全与隐私处理、成本复盘。
10. 产品取舍、已知局限和后续演进方向。

六张截图会被组织为产品流程画廊，并在相关章节再次承担证据说明。

根 README 使用六张圆头耄耋截图的紧凑画廊，并保留另外两个项目的原有截图。
