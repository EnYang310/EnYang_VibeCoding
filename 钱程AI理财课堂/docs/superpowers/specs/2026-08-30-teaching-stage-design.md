# 钱程教学舞台设计

## 目标

把现有“聊天记录 + 异形互动组件”的课堂改为教学型 Agent：主屏给用户一个可读的知识要点，完整讲解以可展开字幕保存；课程主线仍由用户表达“想进入下一个环节”的意图推进。

## 已确认交互

1. 每节课顶部固定显示课程导览；程老师自动发开场讲解，再主动呈现第一道题。
2. 每一张可交互卡都是单选题：题干包含生活情境、当前要判断的问题、三个完整备选项和“确认作答”。不再有拖拽、滑杆、多选、卡内文本输入或行动卡填空。
3. 用户确认答案后，Kimi 生成一段完整讲课内容，而非几句聊天回复。返回分为：屏幕要点（标题、核心结论、最多三条要点）、底部字幕短摘、可展开的完整讲解全文、自然引导语。
4. 屏幕默认只展示要点和当前单选题。字幕控制条始终展示；点击后在全屏/抽屉中按段阅读完整讲解。
5. 用户可随时从底部输入框提问。自由聊天不会跳课；仅当上一题已确认且用户表达进入下一学习环节的意图时，后端执行 `present_interaction_card`。
6. 最后一题确认后，程老师做完整收束讲解，明确课程知识点已经讲完，并进入普通自由聊天；不再触发互动题。
7. 桌面端课堂舞台占用可用宽度（最大 1180px），不被伪装成手机宽度；移动端采用 100svh、无左右大留白、单列布局和底部安全区。

## 内容结构

每门课保留 1 张不可操作的课程导览和 7 张单选互动卡，共 42 道。每张题卡的教学对象为一个明确判断点；确认后由该题对应的课件证据生成讲解。课程数据保存 `questionContext`、`screenTitle`、`screenKeyPoints`、`options`、`correctOption`、`teachingGoal`，不让模型编造题目。

## API 契约

`ChatResponse` 新增 `teaching_scene`：

```json
{
  "screen_title": "日期明确的钱，先保可用性",
  "screen_summary": "房租和报名费不是“闲钱”，它们已经有了日期。",
  "key_points": ["用途让钱不混在一起", "日期决定谁先被保护", "临时支出需要有自己的缓冲"],
  "subtitle_excerpt": "先分任务，再考虑钱放在哪里。",
  "full_caption": ["第一段讲解", "第二段讲解", "第三段讲解"]
}
```

Kimi 必须只根据课件和固定题目生成该对象；长度要求为 3–5 个段落、每段 45–110 字。解析失败或模型不可用时，后端从课件生成同一结构的兜底讲解，不让界面退回短气泡。

## 画面层级

`ClassroomStage`：课程信息、主知识要点、当前题卡；`CaptionDock`：字幕短摘与“展开字幕全文”；`CaptionSheet`：全屏字幕；`ChatComposer`：始终可用。历史消息在“课堂记录”抽屉中保留，不占用默认舞台。

## 来源与设计依据

参考截图中的豆包爱学画面，采用“舞台要点 + 底部字幕 + 展开全文”的层次；不是复制其产品。该层次符合渐进披露：把当前任务与核心信息留在主界面，细节在用户需要时展开。[Interaction Design Foundation](https://ixdf.org/literature/topics/progressive-disclosure) 的说明与 [AI Educational Video Assistant 研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC10862517/) 对“要点提取 + 可读字幕”的实现方向一致。
