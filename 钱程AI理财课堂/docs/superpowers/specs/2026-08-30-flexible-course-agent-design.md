# 钱程：自由对话与严谨课纲设计规格

## 设计目标

让用户在每节理财启蒙课中可以随时、无限轮地与 AI 对话，同时保持六节课程的知识边界、教学目标、互动顺序和金融合规风险可控。AI 是会因人而异的老师，不是课程事实的来源，也不是决定用户是否“有资格”继续学习的裁判。

## 核心决定

### 1. 课件是唯一知识来源

课程内容由一份总教师手册与六份课程课件构成，而非从模型记忆中生成：

```text
financial-learning-teacher/SKILL.md       # 通用老师人格、ELI5表达、合规总规则
references/01-money-jobs.md               # 第1课
references/02-safety-net.md               # 第2课
references/03-product-map.md              # 第3课
references/04-tradeoffs.md                # 第4课
references/05-future-date.md              # 第5课
references/06-steady-mind.md              # 第6课
```

每份课件必须具备以下可结构化读取的区块：

1. `learning_objectives`：完成本课后应理解的 2–3 个判断原则。
2. `core_claims`：老师可使用的事实与解释，附来源/适用边界。
3. `must_cover`：不可跳过的课程锚点。
4. `misconceptions`：常见误区及对应的澄清方式。
5. `scenario_variants`：可按用户处境替换的模拟情境。
6. `activities`：每个固定教学回合的输入、确定性后果与完成条件。
7. `advance_check`：进入下一回合前应出现的互动提交条件；不用于评判用户价值。
8. `compliance_boundaries`：禁答范围和安全替代说法。
9. `source_notes`：供维护者核对的资料链接或依据。

模型不可把课件未覆盖的金融事实伪装成确定结论。需要扩展时，先新增和审核课件内容，再允许模型使用。

### 2. 三条状态轨道彼此独立

| 轨道 | 保存内容 | 谁有权改变 | 用途 |
| --- | --- | --- | --- |
| 课程进度轨 | `course_id`、`unit_id`、互动提交、跳过标记 | 确定性课程引擎和用户明确点击 | 决定当前界面与下一固定回合 |
| 学习画像轨 | 掌握度、易混淆标签、偏好案例、待回看问题 | 规则工具根据互动/对话摘要更新 | 决定解释深浅、补充卡与下个情境版本 |
| 对话轨 | 当前回合摘要、最近有限轮消息、用户问题 | AI 会话服务 | 允许无限聊天，但不推进课程 |

任何一条普通聊天消息都不能改变课程进度。模型返回的“你已经理解了”只是一条鼓励和推荐，不能自动切到下一关。

### 3. 继续权在用户，不在 AI

每个固定回合都有三个显式出口：

- **提交互动**：用户完成本回合的操作/选择，进入结果或下一回合。
- **问问老师**：留在当前回合无限聊天；AI 始终带着该回合的目标和课件证据回答。
- **先继续**：允许用户离开当前回合，课程引擎写入 `skipped_unit_id` 和 `review_reason=learner_skipped`，在结课复盘卡出现“待回看”。

这样既不会因为模型判断不稳定而卡住用户，也不会把未做互动伪装成已掌握。课程最终仍完整呈现，待回看内容可在结课后或首页重新进入。

### 4. AI 的自由度与边界

AI 可以根据学习画像自由改变：

- 例子的生活语境、数字量级和措辞；
- 追问的难度和解释的颗粒度；
- 是否推荐一个可选补充卡；
- 对用户理由的回应顺序和情绪支持方式。

AI 不能改变：

- 六节课的学习目标、固定锚点、互动顺序和确定性后果；
- 页面/组件类型、已完成状态或跳关行为；
- 真实产品或交易建议的结论。

### 5. 金融合规边界

用户可以问任何问题，AI 先判断问题类型：

| 提问类型 | 回应方式 |
| --- | --- |
| 课程概念、模拟选择、个人困惑 | 结合当前课件，用 ELI5 教学法回答并可继续追问。 |
| 真实标的、买卖时点、仓位、个人资产配置 | 只解释相关通用概念和风险，明确不构成建议；不输出买卖结论、配比或收益预期。 |
| 真实账户、身份证、手机号、银行卡等敏感信息 | 提示不要在对话中发送，并引导删除/改用不含身份信息的描述。 |
| 课件外且需要事实核验的问题 | 说明本课不做未经核验的判断，建议查官方资料或咨询持牌机构。 |

## 受控 AI 请求与响应

每次请求服务端只携带最小必要上下文：

```json
{
  "course_id": "money-jobs",
  "unit_id": "consequence",
  "course_evidence_ids": ["money-jobs.core-2", "money-jobs.misconception-1"],
  "activity_summary": {"allocation_tags": ["living", "future"], "event": "unexpected-expense"},
  "learner_profile": {"mastery": 1, "confusions": ["liquidity"]},
  "conversation_summary": "用户担心三个月后不够用",
  "user_message": "那把钱都放活期是不是最安全？"
}
```

模型必须返回可校验 JSON：

```json
{
  "reply": "……",
  "evidence_ids": ["money-jobs.core-2"],
  "learning_signals": ["liquidity_confusion"],
  "suggested_optional_card": "cash-date-check",
  "advance_recommendation": "stay_or_continue",
  "compliance_mode": "education_only"
}
```

`advance_recommendation` 只影响界面文案（如“你已经可以继续，也可以再问我”），服务端与客户端都不允许它直接改变 `unit_id`。若 `evidence_ids` 不属于当前课件、JSON 无效或内容触发合规拒绝，后端返回本地预写教学提示。

## 回合模型

每课固定 8 个回合：开场、初始判断、第一次动手、后果变化、AI 回合一、迁移挑战、AI 回合二、行动卡与复述。AI 对话是挂在每一个回合上的侧边能力，不作为新的课程回合计数。

因此“聊 20 轮”不会让课程变成 20 个散乱页面；聊天始终锚定当前回合。用户在任意时刻关掉聊天，仍看见他刚才的互动和三个明确出口。

## 验收标准

1. 连续发送任意 20 条聊天消息，`unit_id` 不变化。
2. 点击“先继续”后，`unit_id` 改变且该回合被标记待回看；结课复盘中可重新打开。
3. 提交互动后，确定性规则计算结果，不依赖 Kimi 的主观判断。
4. 相同课件锚点下，两个不同学习画像得到不同例子或追问；两者均可追溯到同一 `evidence_id`。
5. 对“我现在应该买 X 吗？”不输出买卖指令，返回教育解释和风险提示。
6. 离开并重进课程，恢复到最后一个已保存的回合与对话摘要；“从头开始”只删除本课程三条状态轨。

## 非目标

- 不以 AI 替代持牌投资顾问。
- 不保存无限历史对话或敏感财务信息。
- 不让模型实时创建新课程、评分门槛或 UI 流程。
